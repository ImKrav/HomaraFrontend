peticiones en vuelo (ver DEF-05) y los efectos de React que se ejecutan tarde en
el iframe de Component Testing (marcador `EfectosListos`, sin `cy.wait(ms)`).

## Diseño de las pruebas

- **Datos aislados**: cada prueba crea su propio usuario CUSTOMER por API
  (`cy.crearUsuarioApi`, correo único con marca de tiempo) y, cuando necesita
  stock o reseñas controlados, su propio producto como ADMIN
  (`cy.crearProductoApi`) que elimina al final. Los pedidos cuyo estado se cambia
  son creados por la misma prueba. No se modifica ningún dato sembrado.
- **Sesión**: `cy.session` con login real por la interfaz (`cy.iniciarSesion`,
  usuarios sembrados) o inyectando el token emitido por el backend
  (`cy.iniciarSesionConToken`, usuarios de la prueba), cacheada entre pruebas.
- **Sincronización**: `cy.intercept` + `cy.wait('@alias')` sobre las peticiones
  reales y aserciones reintentables; nunca `cy.wait(ms)`.
- **Aserciones**: sobre la UI (textos de `app/lib/locales/es.json`), sobre la
  petición enviada (cuerpo) y sobre la respuesta/estado del backend.
- **Defectos**: las pruebas `DEF-xx` fijan el comportamiento observado (como el
  `test.fails` de la suite Vitest); su columna "Resultado obtenido" lo indica.

## Defectos encontrados

Severidad: **Crítica** (seguridad/datos de terceros), **Alta** (rompe una
funcionalidad o bloquea a un usuario), **Media** (funciona con errores visibles o
incumple una regla), **Baja** (cosmético/menor). Los defectos de accesibilidad e
interfaz (DEF-12 a DEF-26) se detallan en
[INTERFAZ-ACCESIBILIDAD.md](INTERFAZ-ACCESIBILIDAD.md) y
[RENDIMIENTO-FRONTEND.md](RENDIMIENTO-FRONTEND.md).
